# Running several Claude Code accounts on one machine

Claude Code stores everything for one account under a config directory chosen by
`CLAUDE_CONFIG_DIR`, defaulting to `~/.claude` (with the main config file at
`~/.claude.json`). A second account means a second directory — and by default a
second copy of your skills, plugins, hooks, transcripts and memory, plus a separate
peer registry, so sessions on different accounts cannot see each other.

The goal here is one workspace, several identities.

## Setup

```sh
# 1. Create a profile and log in to the second account
CLAUDE_CONFIG_DIR=~/.claude-work ANTHROPIC_NO_KEYCHAIN=1 claude   # then /login

# 2. Point its shareable parts at ~/.claude
~/.dotfiles/shared/.claude/link-profiles.sh

# 3. Verify any time
~/.dotfiles/shared/.claude/link-profiles.sh --check
```

The script discovers every `~/.claude-<name>/` that has its own `.claude.json`, so
adding a profile later needs no edit. It merges before linking and backs up anything
it replaces.

Shell functions live in `~/.zshrc.local` (never committed — it holds account names).
`macos/.zshrc` only sources it. The functions are generated by globbing, so a new
profile becomes `claude-<name>` on the next shell without touching any file:

```sh
for _cc_dir in "$HOME"/.claude-*(N/); do
  [[ -f "$_cc_dir/.claude.json" ]] || continue
  _cc_name="${${_cc_dir:A:t}#.claude-}"
  eval "claude-${_cc_name}() { CLAUDE_CONFIG_DIR=\"\$HOME/.claude-${_cc_name}\" ANTHROPIC_NO_KEYCHAIN=1 \"\$(_claude_bin)\" \"\$@\" }"
done
```

## What is shared, and what must not be

| Path | Shared | Why |
|---|---|---|
| `sessions/` | yes | peer registry — see below |
| `projects/` | yes | transcripts *and* `memory/` live here |
| `skills/` | yes | install once |
| `plugins/` | yes | install once |
| `settings.json` | yes | hooks, statusline, permissions |
| `CLAUDE.md` | yes | global instructions |
| `.claude.json` | **no** | holds `oauthAccount` |
| `.credentials.json` | **no** | per-account token |
| `settings.local.json` | **no** | per-profile override |
| `history.jsonl` | **no** | concurrent appends can interleave |

`.claude.json` is the one that cannot be shared, and it is worth being precise about
why: `oauthAccount` is a *single* field naming the active account. Share the file and
the last writer overwrites every other identity — the very thing separate profiles
exist to prevent. Claude Code also rewrites this file constantly (project state, prompt
history), so two concurrent sessions can corrupt it.

Everything people actually want out of a shared `.claude.json` is reachable another
way: projects and memory through `projects/`, and MCP servers through a `.mcp.json`
in the repo root, which every profile reads because it lives with the code rather
than in a config dir.

## Peer messaging across accounts

`ListAgents` / `SendMessage` between local sessions has two halves:

- **Transport** — a unix socket at `/tmp/cc-socks/<pid>.sock`. Already global.
- **Discovery** — `<CONFIG_DIR>/sessions/<pid>.json` plus a `.key`. Per profile.

So discovery is the only thing standing between two accounts, and linking `sessions/`
is enough. Verified: a session started with `CLAUDE_CONFIG_DIR=~/.claude-work`
registers into `~/.claude/sessions/` through the symlink and appears as a peer to a
default-profile session on a different account, in both directions.

## Per-profile preferences still work

`settings.json` is shared, but `settings.local.json` overrides it and stays local, so
each profile keeps its own `model`, `theme`, `tui`, `effortLevel`.

## Notification sounds

`shared/.claude/sounds/play.sh` maps a hook event (`stop`, `fail`, `permission`,
`subagent`) to a file in its own directory, falling back to the built-in macOS sounds.
It hardcodes `$HOME/.claude/sounds`, not `$CLAUDE_CONFIG_DIR`, so every profile
resolves to the same sounds with no extra linking.

```sh
touch ~/.claude/sounds/mute            # silence everything
touch ~/.claude/sounds/subagent.mute   # silence one event
echo 0.4 > ~/.claude/sounds/volume     # 0.0 - 2.0
```

## Gotchas

- **Symlinks can be replaced silently.** A tool that saves by writing a temp file and
  renaming will turn a linked `settings.json` back into a regular file, and sharing
  stops with no warning. Run `link-profiles.sh --check` after changing settings
  through the UI.
- **Trust dialogs are per profile.** Opening a folder under a second account prompts
  again — project *registration* lives in `.claude.json`, which is not shared. The
  transcripts and memory are already there.
- **Keep secrets out of the repo.** MCP credentials belong in `~/.zshrc.local` as
  exports, referenced from `.mcp.json` as `${VAR}`. Hook scripts that embed
  infrastructure names or resource IDs should stay in `~/.claude/hooks/`, which this
  repo does not track. Those files then have no backup anywhere, so
  `backup-private.sh` copies them somewhere private (iCloud Drive by default) and
  `--restore` puts them back after a reinstall. It copies rather than symlinks: iCloud
  evicts cold files, and a hook or shell function that vanishes at startup fails
  silently.
- **Attribution.** `includeCoAuthoredBy: false` and empty `attribution` in
  `settings.json` stop `Co-authored-by:` trailers. Removing an entry that already
  reached GitHub's contributor list is a separate problem: the trailer may be gone from
  every ref while the sidebar still shows it, because unreachable commits are pruned on
  GitHub's own schedule (documented as up to 30 days). Rewriting history does nothing
  once no trailer remains — check with `git log --all --format='%b' | grep -c
  'Co-authored-by:'` before touching anything.
